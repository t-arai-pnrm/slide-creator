# 要素選択のフレームワーク

適切な HTML 要素を選択するためのクイック判断フレームワーク。

## リストか？

```
アイテム数を知ることがユーザーの役に立つか？
├─ はい → アイテムに順序やランクがあるか？
│         ├─ はい → <ol>
│         └─ いいえ → <ul>
├─ いいえ → 用語と説明のペアか？
│           ├─ はい → <dl>
│           └─ いいえ → 適切な構造を持つプレーンな要素を検討
└─ ツールバーのコマンド群か？
   └─ はい → <menu>
```

## テーブルか？

```
データに意味のある行と列の両方があるか？
├─ いいえ → テーブルではない
│           ├─ 1次元のみ → リストまたはプレーンな要素
│           ├─ キー・バリューペア → <dl>
│           └─ 階層的 → ネストしたリストまたは他の構造
└─ はい → 各行が同じカラムを持つか？
          ├─ いいえ → データ構造を再検討
          └─ はい → 完全なセマンティクスを備えた <table> を使用
```

## ボタンかリンクか？

```
新しい URL へ遷移するか？
├─ はい → <a href="...">
└─ いいえ → アクションが発生するか？
            ├─ はい → JS が失敗した場合に URL が有用なフォールバックを提供するか？
            │         ├─ はい → <a href="..."> に JS で拡張
            │         └─ いいえ → <button>
            └─ いいえ → そのインタラクションが本当に必要か再検討
```

## `section` か `div` か？

```
このコンテンツはテーマ的なグループを形成するか？
├─ いいえ → <div>
└─ はい → 意味のあるアクセシブルな名前を付けられるか？
          ├─ はい → <section aria-labelledby="...">
          └─ いいえ → <div>（ラベルなしの section ≈ セマンティック的に div）
```

## `article` の候補か？

```
このコンテンツは単独で意味を成すか？
├─ はい → シンジケートまたは抽出が可能か？
│         ├─ はい → <article>
│         └─ いいえ → 適切なコンテナ（section, div 等）を使用
└─ いいえ → 適切なコンテナ（section, div 等）を使用
```

## どのランドマークか？

```
このセクションの目的は何か？
├─ サイト / セクションの冒頭 → <header>
├─ サイト / セクションの末尾 → <footer>
├─ ナビゲーション → <nav>（ラベル必須）
├─ ページの主要コンテンツ → <main>
├─ 検索機能 → <search>（フォーム自体。検索結果ではない）
├─ ユーザー入力 → <form>（ランドマークにするにはラベル必須）
├─ 間接的に関連するコンテンツ → <aside>
├─ 自己完結したコンテンツ → <article>
└─ ラベル付きのテーマ的グループ → <section aria-labelledby="...">
```

## フォームフィールドのグループ化

```
これらのフィールドは論理的 / テーマ的なグループを形成するか？
├─ はい → <fieldset> と <legend>
│         例: 住所フィールド、個人情報、同意チェックボックス
└─ いいえ → 視覚的なグループ化が必要か？
            ├─ はい → <div> に適切なスタイリング
            └─ いいえ → ラッパーなしでフィールドを配置可能
```

## インタラクティブなディスクロージャー

```
コンテンツを展開 / 折りたたみ可能にすべきか？
├─ はい → 単一のコンテンツセクションか？
│         ├─ はい → <details> / <summary>
│         └─ いいえ → タブパターンまたはカスタムディスクロージャーを検討
└─ いいえ → 定義のリストか？
            └─ はい → <dl>（details / summary ではない）
```
