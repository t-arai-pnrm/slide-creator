# 素材: Safari 27.3 betaの「適応型ダークモード」で、ダークモード未対応のサイトが受ける影響と対策

- 著者: TAK（frontmatter の author）
- URL: https://www.tak-dcxi.com/article/safari-adaptive-dark-mode/
- 言語: 日本語

記事の frontmatter: date 20261110、category「Web Topics」、tags「Safari」、via taklog。description は「Safari 27.3 betaの「適応型ダークモード」は、ダークモード未対応のサイトを自動で暗くします。実際のサイトでの見え方、変換の仕組み、color-schemeの正しい宣言、起きうる問題をまとめます。」

## 主張の骨子

いちばん言いたいこと: 適応型ダークモードはダークモードのユーザーには便利だが、ダークモード未対応のサイトの制作者にとっては、ユーザーの設定によって意図しない見た目の変化が起きうる機能なので、表示を確かめ、必要なら対応を決めるべきだ（まとめ）。

支える主張（記事の順）:

1. Safari 27.3 beta に「適応型ダークモード」（Adaptive Dark Mode）が登場した。ユーザーが有効にすると、サイトが未対応でも、背景色・文字色・SVG・グラデーションなどを解析して自動でダークモードに変換する（導入）。
2. WebKit の記事によると、ページ読み込みの約40%はダークモードのユーザーによるが、ダークモード対応ページの読み込みは約10%にとどまる。この差を埋め、Web 全体で一貫した暗い表示を提供することが目的とされている（導入）。
3. 求めていた人には朗報だが、ユーザーの設定次第で見た目が変わるので、既存サイトの制作者にも影響が及ぶ可能性がある（導入）。
4. 有効化は、システムの外観がダークで背景の明るいサイトを開いたときの提案から。条件が緩いので、設定に疎いユーザーにも浸透する可能性が高い（有効化する方法）。
5. 変換は単純反転ではなく、色相を保ち明度を反転するカラーマトリクス。明るいページだけを原則変換し、画像と canvas は基本的に変換しない。SVG と単純な白黒ビットマップは変換されることがある（仕組み）。
6. Yahoo! JAPAN のトップは自然に変換されたが、背景に画像を敷くページはうまく変換されないことがある（実際のサイト）。
7. `color-scheme: light dark` を宣言したサイトは対象外。宣言は `<meta>` 推奨。変換を避けるためだけに未対応サイトで `light dark` を宣言してはいけない。背景が暗いサイトは `dark only`、変換を抑えたいときは `light only`。ただし Safari 27.3 beta 1 では `only` による抑止は未対応（対象から外れる条件）。
8. 既存サイトで起きうる問題: 背景画像上の文字が読みにくくなる、`mix-blend-mode` やマスクが無効になる、背景色と画像・SVG の配色が揃わない、canvas と周囲の食い違い、JavaScript からは変換前の色しか取れない（既存のサイトで起きうる問題）。
9. WebKit は5つの対応を勧めている。一番確実なのは制作者側でのダークモード対応だが、フルスクラッチの制作では両対応はデザイナーのコスト的に厳しく、ブラウザに委託するのがベターかもしれない（WebKitが勧めている対応）。
10. ダークモード対応は必須ではなく選択肢の一つ。ただし適応型ダークモードの登場で、対応しないことの意味は変わる（そもそもダークモードに対応するべきか）。
11. 特に `mix-blend-mode`、マスク、`<canvas>`、背景色を焼き込んだ画像を使うサイトは影響を受けやすい。Safari 27.3 で確かめ、余裕がなければ `color-scheme: light only` も検討する（まとめ）。

## 節の構成

### （導入。見出しなし）

- Safari 27.3 beta で新機能「適応型ダークモード」（英語名は Adaptive Dark Mode）が登場した。
- WebKit の記事へのリンクカード: https://webkit.org/blog/18541/introducing-adaptive-dark-mode/
- ユーザーが有効にすると、サイトがダークモード未対応でも、Safari が背景色・文字色・SVG・グラデーションなどを解析し、自動でダークモードに変換する。
- WebKit の記事によると、Web のページ読み込みのうち約40%はダークモードのユーザーによるものだが、**ダークモードに対応したページの読み込みは約10%にとどまる**（太字は原文）。この差を埋め、Web 全体で一貫した暗い表示を提供することが目的とされている。
- 待望の強制ダークモードで、求めていた人には朗報な機能。ただしユーザーの設定次第で見た目が変わるので、既存のサイトの制作者にも影響が及ぶ可能性がある。

### 「適応型ダークモード」を有効化する方法

- システムの外観をダークにした状態で、背景の明るいサイトを開くと、Safari が適応型ダークモードのプレビューを提案する。そこで「Try」を選ぶと有効になる。
- 現在は beta 版のみなので、この先どうなるかは分からない、と著者は述べる。
- 「システムの外観をダークにする」という緩い条件で提案されるので、Safari の設定に疎いユーザーにも浸透する可能性が高い、と著者は見る。

### ダークモード変換の仕組み

#### 単純な色の反転ではない

- CSS で定義された色をそのまま反転するのではなく、色相を保ったまま明度を反転するカラーマトリクスで変換する。明るい背景は暗く、暗い文字は明るくなる。
- テキストは WCAG のコントラスト比 4.5:1 を目標に調整される。必ず 4.5:1 を満たすと保証されているわけではない。明るい CSS のグラデーションも暗く変換される。
- すべての色を変換するわけではない。装飾としての色と意味を持つ色を見分け、見えなくならないよう反転すべき色とそのまま残すべき色を判断しているとのこと。著者の注記: （この辺りは Safari の判断に依ります）

#### 変換するかどうかはページの色から判断する

- ダークモードへの対応を宣言していないページでは、Safari がページの色を解析し、全体として明るいか暗いかを推定する。
- そのため、デフォルトで暗い背景に明るいテキストのページなら何も変化は起こらないようだ（推量の表現）。原則的に明るいページだけを暗く変換する。

#### 画像や canvas は基本的に変換しない

- 写真などの画像は基本的にそのまま表示する。この辺りは強制カラーモードと同じ。ただし適応型ダークモードは、ユーザーが指定したパレットに色を置き換える強制カラーモードとは別の機能。
- `<canvas>` の内容も変換されない。canvas に描かれる内容は幅が広く、予測できないため。
- ただし、背景が暗くなるとアイコンやロゴの多くはコントラストが足りなくなる。そのため、次の2つは変換されることがある。
  - SVG画像: 中の色を調べ、必要に応じて変換される
  - ビットマップ画像: ピクセルのヒストグラムを解析し、単純な白黒のロゴなら反転される

### 実際のサイトでの見え方

- Safari 27.3 beta で、実際のサイトに適応型ダークモードを当てた。
- 確かめた Yahoo! JAPAN のトップページは、比較的自然で読みやすい表示になった。背景は暗く、文字は明るく変換され、ロゴ、アイコン、ニュースの写真は元の色のまま残っている。
- 画像1枚（「図と画像」参照）。
- 一方、背景に画像を敷いているページはうまく変換されないことがある。例は後の「既存のサイトで起きうる問題」で紹介する。

### 対象から外れる条件

#### `color-scheme: light dark`を宣言しているサイトは変換されない

- すでにダークモードに対応し、`color-scheme` で `light dark` を宣言しているサイトは、適応型ダークモードの対象にならない。宣言は HTML の `<meta>` 要素と CSS のどちらでもよい。（コードは「コード」参照）
- WebKit の記事は、JavaScript で後から差し込むのではなく、HTML の `<head>` や `:root` の CSS で最初から宣言するよう勧めている。
- 著者は `color-scheme` を `<meta>` 要素で書くことを推奨する。理由: CSS で書くと、ブラウザは CSS を読み込んで解析するまでページの配色を決められず、読み込みの途中で背景が白や黒にちらつく可能性がある。`<meta>` ならCSSを待たずに配色をブラウザに伝えられるので、初期描画時の配色の切り替わりを抑えられる。CSS を読み込めなかった場合も、背景色とスクロールバーやフォーム部品の配色がユーザーの設定に従う。
- 仕様上はどちらで書いてもよいが、著者は、CSS で書くのはコンポーネント単位で配色を変える場合や、CSS を HTML にインラインで埋め込んでいて読み込みの遅れを気にしなくてよいときに限るのがよいと考えている。

#### ダークモードに対応していないなら`light dark`を宣言しない

- 変換を避けたいからといって、未対応のサイトで `color-scheme: light dark` を宣言してはいけない。この宣言は「このページはダークモードの配色にも対応している」という意味で、OS の外観がダークのとき、ブラウザはページの既定の背景色と文字色を暗い配色のシステムカラーにする。
- 背景色や文字色の指定がなければ、このシステムカラーが当たる。例えば文字色だけを暗い色で指定し背景色を指定していなければ、暗くなった背景の上に暗い文字が載り、同化して読めなくなる。フォーム部品やスクロールバーも暗い見た目で描かれ、明るいデザインの中で浮く。
- 自分で書いた覚えがなくても、海外製のリセット CSS やフレームワークが `color-scheme: light dark` を宣言していることがある。著者は普段ダークモードでブラウジングしており、たまにテキストと背景が同化しているサイトを見かける。未対応なら既存サイトの CSS も確かめ、この宣言を取り除いておきましょう、と述べる。
- 背景が暗いサイトの場合は `dark only` を宣言しておくとよい。ユーザーの外観の設定に関係なく、スクロールバーやフォーム部品も暗い見た目になり、ページと配色が揃う。（コード参照）
- 背景が明るいサイトの場合は、`color-scheme` は何も指定しなくてよい。ただし適応型ダークモードの変換も避けたいときは、次に紹介する `light only` を宣言する。

#### `color-scheme: light only`で変換を抑える

- ダークモードに対応する予定がなく明るい表示のままにしたい場合は `light only` を宣言する。（コード参照）
- CSS で書く場合は、`:root` ではなく特定の要素に指定することもできる。
- ArticleNote（原文）: 「Safari 27.3 beta 1では、`only`による適応型ダークモードの変換抑止は未対応です。いつ対応するかは示されていないので、今後のbetaで確かめたいと思います。」

#### ページの一部だけを外す

- ページの一部だけを変換から外したい場合や、コンポーネント単位で配色を変えたい場合は、その要素に `color-scheme: light dark` を指定し、ダークモードのスタイルを自分で書く。（コード参照）

### 既存のサイトで起きうる問題

#### 背景画像の上の文字が読みにくくなることがある

- WebKit の記事によると大半の画像は変換されない。画像の上の文字の見やすさも考慮するとされているが、明るい背景画像が変換されず、その上の文字だけが明るく変換されると、コントラストが不足することがある。
- 例: 龍が如くポータルのニュース一覧は、明るい背景画像の上に文字を置いている。適応型ダークモードでは記事の題名や日付が明るい色に変換され、背景画像に同化してほとんど読めなくなった。
- 画像1枚（「図と画像」参照）。
- WebKit の記事も、背景にタイル状の画像を敷かず CSS の単色やグラデーションを使うよう勧めている（後の「WebKitが勧めている対応」を参照）。文字を載せる背景を画像で描いているサイトは、適応型ダークモードで表示を確かめておきましょう、と著者は述べる。

#### `mix-blend-mode`やCSSのマスクが無効になることがある

- 色を変換した要素にマスクや `mix-blend-mode` をかけると、意図しない結果になることがある。そのため、適応型ダークモードはこれらの効果を無効にする場合がある。
- ブレンドモードで文字や画像の色を背景になじませているデザインや、マスクでアイコンの形を描いている実装は、見た目が変わる可能性がある。

#### 背景色と画像やSVGの配色が揃わなくなる

- 背景色は変換される一方で、写真などの画像は変換されない。SVG や白黒のロゴは変換されることがある。
- そのため、画像の中に背景色を焼き込んでいる場合（白い背景のロゴ画像を白い背景に置いているなど）、暗くなった背景の上に白い四角が浮いて見えることがある。SVG だけが変換され、隣のビットマップ画像と配色が揃わない、といったことも起こりうる。

#### canvasと周りのHTMLの見た目が食い違う

- `<canvas>` の内容は変換されないので、canvas で描いたグラフなどが、暗くなった周りの HTML の中で明るいまま表示される。canvas に描いた画像も、元の色のまま描かれる。

#### JavaScriptからは変換前の色しか取れない

- `getComputedStyle()` などで CSS の色を取得すると、変換後の色ではなく、制作者が書いた元の色が返る。CSS の色を読み取って `<canvas>` などに描いている実装では、HTML と `<canvas>` の色がさらに食い違う。
- また、適応型ダークモードが適用されているかどうかを JavaScript から検出することもできない。検出できるとフィンガープリンティングに使える情報が増えるため、プライバシーの観点から隠されている。

### WebKitが勧めている対応

- WebKit の記事は、適応型ダークモードでの見た目を良くするために次の対応を勧めている。
  - ビットマップのロゴやアイコンをSVGにする
  - 背景にタイル状の画像を敷かず、CSSの単色やグラデーションを使う
  - 角丸、影、ボタンの状態を、画像のスプライトではなくCSSで描く
  - コンテンツの画像は、ページの背景色を焼き込まず、透過した背景で作る
  - コンテナにpaddingを足し、要素が詰まらないようにする
- 著者: 一番確実なのは制作者側でダークモードに対応すること。`color-scheme`、`prefers-color-scheme` のメディアクエリ、`<picture>` の `<source media="(prefers-color-scheme: dark)">`、`light-dark()` 関数などを使えば、変換を Safari に任せずに済む。ダークモード対応の UI ライブラリを用いるのも手でしょう、と述べる。
- しかし、UI ライブラリを用いる Web 開発の分野はともかく、オリジナルのデザインをフルスクラッチで実装する Web 制作の分野では、ライト/ダーク両対応のサイトを作るのはデザイナーのコスト的にも厳しい。そのような環境ではブラウザを信用して配色変更を委託するのがベターかもしれない（推量の表現）。

### そもそもダークモードに対応するべきか

- 適応型ダークモードの登場で、ダークモード対応を改めて考えた制作者も多いと思う。ただし対応の必要性や効果はユーザーや利用環境によって異なる。よく挙げられる理由と補足・条件は次の表のとおり。

| 理由 | 補足・条件 |
| --- | --- |
| 暗い場所での使いやすさ | 私がダークモードを利用しているのがこの理由。暗い環境で明るい背景を見るのはしんどい。しかし、暗い背景に明るい文字は輪郭がにじんで見えて焦点を合わせにくいという指摘もある。 |
| バッテリーの節約 | 有機ELのディスプレイでは黒い画素が発光しないのでバッテリーの節約が見込まれる。バックライトで光らせる液晶では効果がない。有機ELでも効果の大きさは画面の明るさや表示内容によって異なる。 |
| ロービジョンの人や光に敏感な人の見やすさ | AndroidのガイドラインがOSの機能として挙げている理由。Appleのアクセシビリティの評価基準も、明るい画面で痛みや不快感を覚える人への配慮を挙げている。 |
| 見た目の好み | 黒い背景はクールでかっこいい。ただ、人の感性に依る。 |

- Android も Apple も、暗い環境での見やすさや明るい光に敏感なユーザーへの配慮を挙げているが、見やすい配色は人や環境によって異なる。こうして見ると、ダークモード対応は必須ではなく、ダークモードを好むユーザーやダークモードのほうが見やすい環境に応える選択肢の一つと言える。
- リンクカード2つ: https://developer.android.com/develop/ui/views/theming/darktheme 、https://developer.apple.com/help/app-store-connect/manage-app-accessibility/dark-interface-evaluation-criteria/
- ただし、適応型ダークモードの登場で、対応しないことの意味は変わる。ユーザーがこの機能を有効にしている場合、何も指定しなければ Safari によって暗く変換される可能性がある。制作者は、自動変換を受け入れるか `light only` で変換を抑えるかを検討する必要がある。
- なお、Safari 27.3 beta 1 では `only` による変換抑止は未対応。今後の beta で対応状況を確認する必要がある。
- また、`light only` を明示すると、ユーザーが求めている機能を無効にすることになる懸念もある。

### まとめ

- 適応型ダークモードは、ダークモードのユーザーには便利。一方で、未対応サイトの制作者にとっては、ユーザーの設定によって意図しない見た目の変化が起きうる機能でもある。
- 特に `mix-blend-mode`、マスク、`<canvas>`、背景色を焼き込んだ画像を使っているサイトは影響を受けやすい。既存サイトも Safari 27.3 で表示を確かめておいたほうがよい。不具合があり対応する余裕がない場合は、`color-scheme: light only` の宣言も検討するとよい。ただし Safari 27.3 beta 1 では `only` による変換抑止は未対応なので、今後の beta で対応状況を確かめる必要がある。
- 明らかに変換がうまくいっていないサイトを見つけた場合は、Feedback Assistant で報告できる。サイトの制作者は web-evangelist@apple.com に相談することもできるとのこと。

## コード

### html（節: `color-scheme: light dark`を宣言しているサイトは変換されない）

```html
<meta name="color-scheme" content="light dark" />
```

### css（同じ節）

```css
:root {
	color-scheme: light dark;
}
```

### html（節: ダークモードに対応していないなら`light dark`を宣言しない。背景が暗いサイト向け）

```html
<meta name="color-scheme" content="dark only" />
```

### html（節: `color-scheme: light only`で変換を抑える）

```html
<meta name="color-scheme" content="light only" />
```

### css（同じ節）

```css
:root {
	color-scheme: light only;
}
```

### css（節: ページの一部だけを外す）

```css
.chart {
	color-scheme: light dark;
	background-color: light-dark(#fff, #1c1c1e);
	color: light-dark(#1c1c1e, #f2f2f7);
}
```
