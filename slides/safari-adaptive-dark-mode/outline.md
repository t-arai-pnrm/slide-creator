# 構成案: Safari 27.3 beta の「適応型ダークモード」で、未対応のサイトが受ける影響と対策

- 目的: 適応型ダークモードが自分のサイトの表示をどう変えるかを知り、`color-scheme` の宣言を選べるようになり、確かめる箇所を持ち帰る
- 聞き手: Web サイトを作る人（マークアップ、フロントエンド）。CSS は書けるが、`color-scheme` の値の違いは意識していない人
- 発表の時間: 10 分（19 枚）
- 話さないこと:
  - `dark only` の宣言（背景が暗いサイトは変換の対象にならず、発表の主題から外れるため）
  - ページの一部だけを変換から外す書き方（`.chart` の例。`light only` の説明と混同しやすく、時間も足りないため）
  - ダークモードに対応する理由の表の 4 行（暗い場所、バッテリー、ロービジョン、好み）の中身（結論の「必須ではなく選択肢の一つ」だけを話すため）
  - WebKit が JavaScript で後から宣言する書き方を勧めていない点と、強制カラーモードとの違い（どちらも補足の細部のため）
  - Feedback Assistant と web-evangelist@apple.com の案内（最後のスライドのノートで話し、スライドには書かない）
- 章の扉は入れない（5 つのパートに扉を足すと、10 分の上限の 20 枚を超えるため）

## ノートに回すこと

- 10 枚目: 海外製のリセット CSS やフレームワークが `light dark` を宣言していることがある。フォーム部品とスクロールバーも暗く描かれる
- 15 枚目: 検出できない理由は、フィンガープリンティングに使える情報を増やさないため
- 17 枚目か 18 枚目: `light only` を宣言すると、ユーザーが求めている機能を無効にすることになる
- 18 枚目: フルスクラッチの制作では、ライトとダークの両方に対応する費用が大きい。著者は、ブラウザに配色の変更を任せるほうがよいかもしれないと書いている
